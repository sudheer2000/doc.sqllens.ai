    Technical overview

    Latest SQLLens capabilities — MCP and AI agents, Query Optimizer AI advisory, Excel reporting, connection import, and which engines each feature supports. Written for practitioners who need a concise map of the product surface.

    Latest features

    Recent releases expand AI-assisted tuning, agent access to live databases, and shareable Excel reports across performance modules.

    • MCP & AI database — SQLLens registers as an MCP server; Copilot Agent, Cursor Agent, and @sql / @sqllens chat use saved connection profiles with read-only defaults.
    • Index Strategy Studio — Three tabs on the Query Optimizer Analyze panel: rule-based Index Engine, single-model AI Advisor, and 3 AI compare (LLMs) on MySQL/MariaDB.
    • Excel exports — Standard and Expert workbooks from Query Log Optimizer (QLA), Performance Monitor (PM), Query Profiler, and Query Optimizer (QO).
    • Import connections — Bring in profiles from SQLTools settings.json or DBeaver data-sources.json.
    • Workspace credential scan — On workspace open, scan .env and docker-compose files for database URLs and offer one-click profile creation.
    • Multi-engine QO — Dedicated workbenches for MySQL/MariaDB, PostgreSQL, and SQLite with engine-appropriate plans and index guidance.

    MCP & AI database

    SQLLens exposes a built-in MCP server so AI clients in VS Code or Cursor can work with your saved connection profiles — not ad-hoc connection strings in chat.

    Surfaces

    SurfaceWhat it does
    Copilot Agent / Cursor AgentEnable SQLLens in the tools picker; ask natural-language questions; the agent chains schema discovery and queries.
    @sql and @sqllensChat participants with slash commands (/connections, /schema, …) and fenced sql blocks for execution.
    Active SQL tabWhen an editor tab has an Active database, MCP and chat default to that connection.

    Connection scope & safety

    • Read-only by default — SELECT and schema tools unless you change MCP write policy in Settings.
    • No passwords in tool output — agents see profile names and engine types, not stored secrets.
    • One connection + one database per operation — predictable scope for auditing.
    • First-use consent — a Skyline modal explains access before tools register.
    • SQLite — file-based profiles follow the same MCP tools with path-scoped access.

    Excel exports (Standard & Expert)

    Performance modules can export structured .xlsx workbooks for sharing with DBAs, change review, or archival.

    ModuleStandard reportExpert / full report
    Query Log Optimizer (QLA)Current tab grid (fingerprints, usage, etc.)Summary metrics + recommendation sheets across analyzed queries
    Performance Monitor (PM)Active tab snapshotMulti-tab workbook (dashboard, profiler, locks, …) where available
    Query ProfilerSession grid exportFull profiler workbook with recommendations when Optimize has run
    Query Optimizer (QO)Standard report (Excel) — plan, indexes, scoresExpert report — optional AI suggestions, 3 AI compare groups, rewrite detail, extra sheets

    Export buttons live in each module toolbar (spreadsheet icon). QO Expert opens a sheet picker before export. Expert Index DDL for QLA is separate from Excel — script-oriented output for top-N consolidated indexes.

    Import connections

    Command Palette → SQLLens: Import Connections (or connection tree context) opens a file picker for:

    • SQLTools — VS Code / Cursor settings.json connection entries
    • DBeaver — data-sources.json export

    SQLLens parses MySQL, MariaDB, PostgreSQL, and SQLite entries, shows a multi-select list with host/user/database summary, and saves chosen profiles through the same path as manually added connections. Passwords import when present in the source file; otherwise you complete credentials in the connection dialog.

    Workspace credential import

    On extension activation (and via Scan Workspace for Database Credentials), SQLLens scans the open workspace for:

    • .env and .env.* files
    • docker-compose.yml / docker-compose.yaml service environment blocks

    Recognized patterns include common DATABASE_URL, MYSQL_*, PG*, and SQLite file paths. Example/template env files are skipped. When matches are found, a Skyline modal offers to create connection profiles — deduplicated against profiles you already saved.

    You can snooze or disable future prompts from the modal; scans respect standard ignore folders (node_modules, .git, etc.).

    Architecture notes (high level)

    SQLLens runs as a VS Code extension with these logical layers — useful when reasoning about MCP, QO, and exports:

    • Connection layer — Saved profiles, per-file Active database resolution, engine-specific drivers (MySQL/MariaDB, PostgreSQL, SQLite).
    • Workbench webviews — QO, QLA, PM, Profiler render in editor panels; export and AI actions post messages to the extension host.
    • Optimizer engines — Plan parsers and index recommenders per engine under shared contracts (e.g. join-degree rules shared across PG/SQLite/MySQL).
    • AI gateway — Integrated routing to sqllens.ai Cloud or BYOK providers; QO AI Advisor and 3 AI compare call the same gateway with optimizer-specific prompts.
    • MCP bridge — In-process MCP server registers tools that delegate to ConnectionManager and SQL guard (read-only enforcement, statement classification).
    • Export pipeline — Grid + recommendation data serialized to multi-sheet Excel via a shared grid report builder.
    Settings

    MCP write policy, optimizer defaults, and AI providers are under Settings (skyline-mysql.* prefix).
