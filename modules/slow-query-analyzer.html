    Slow Query Log Analyzer (QLA)

    Aggregate slow-query workload from digest tables, slow logs, or uploaded files — rank fingerprints by impact, batch-analyze with Optimize All, apply index DDL with optional before/after validation, and jump into the single-query Query Optimizer.

    Overview

    The Slow Query Log Analyzer (MySQL/MariaDB) and Query Log Optimizer (PostgreSQL) share one panel. They:

    • Load workload from performance digest (events_statements_summary_by_digest / pg_stat_statements), server slow-log tables, auto-detected log files, or drag-and-drop uploads.
    • Normalize statements (literals → placeholders) into fingerprints and score them by response time, call count, rows examined, and usage share.
    • Prioritize with impact rank, bubble timeline, and usage breakdowns by table, database, and user.
    • Tune in bulk — Optimize All Queries fills index recommendations; Create Indexes + Validate applies DDL and compares EXPLAIN before/after.
    • Drill down — per-row EXPLAIN, single-query Optimize, copy SQL, or export index scripts.
    Naming

    MySQL/MariaDB connections show Slow Query Log Analyzer. PostgreSQL connections show Query Log Optimizer — same panel, engine-specific data sources.

    How to open

    • Database tree — right-click a connection or database → ⚡ Query Log Optimizer (PostgreSQL) or the connection’s slow-query command (MySQL/MariaDB).
    • Command Palette — search for slow query / query log optimizer commands tied to your active connection.
    • Performance Monitor — open the Query Log Optimizer from the debugger workbench when monitoring a session.

    The panel opens scoped to the tree node you picked. Confirm the sidebar Active database matches the workload you intend to tune.

    Home screen — choose a data source

    Before any grid appears, the home screen offers one or more load paths. Filters on each card control time window, row limit, and sort order.

    Action bar (batch operations)

    Right of the main tabs:

    ButtonWhat it does
    ⚡ Optimize all QueriesRuns the Query Optimizer across top fingerprints (scope set in Optimizer Settings). Fills Recommended Indexes column and updates summary tiles. Shows progress banner with cancel.
    Create Indexes + Validate ▼Dropdown: Create Indexes + Validate (EXPLAIN before/after) or Create Indexes only. Opens full-screen Create Indexes overlay.
    Export Index DDL ▼Export indexes script (save file) or Copy indexes script (clipboard). Requires Optimize All first.
    🔍 SettingsOpens Optimizer Settings modal (sampling + Optimize All scope).

    Bubble timeline (Query Fingerprints tab)

    Above the fingerprint table, a scatter timeline plots slow executions over time:

    • Bubble size reflects query duration; color matches impact rank (top 10 highlighted).
    • Hover for timestamp, duration, fingerprint snippet, grade, and quality tag.
    • Click a bubble to scroll and highlight the matching grid row.
    • Toggle/zoom controls collapse or expand the chart when space is tight.

    Operation progress banner

    During Optimize All, Create Indexes, or validation, a status banner appears below the action bar:

    • Status text and badge (Running, OK, Warning, Blocked).
    • Progress bar with percentage and optional ETA chip.
    • Cancel — stops the batch and kills the active server query when possible.
    • Detail chips — thread id, DB state, elapsed time during long operations.

    Create Indexes overlay

    Full-screen flow opened from the action bar. Two phases: selection then results (after Create Indexes or Create Indexes + Validate).

    Selection screen controls

    ControlPurpose
    Select all checkboxToggle all index recommendations.
    Ignore Low impact indexesDeselects low-impact rows from the create list.
    ThreadsParallel CREATE INDEX workers (1, 2, 4, 8, 16). Use 1 on busy production systems.
    Summary stripN selected · Est. total: … — selected count and rough duration estimate.
    Per-row checkboxInclude/exclude individual CREATE INDEX statements.

    Auto-detect & enable slow logging

    QLA probes the server for log configuration:

    • MySQL/MariaDB — reads slow_query_log, slow_query_log_file, and whether mysql.slow_log is writable. Offers enable SQL when logging is off.
    • PostgreSQL — checks logging_collector, log_min_duration_statement, and pg_stat_statements availability.
    Production caution

    Enabling verbose statement logging adds overhead. Use conservative thresholds (long_query_time, log_min_duration_statement) and narrow time windows when loading digest stats.

    Recommended tuning workflow

    1. Load the smallest window that captures the problem (digest is usually enough for MySQL; pg_stat_statements for PostgreSQL).
    2. Filter by database, table, or query text; on PostgreSQL use Tune DB to focus one schema.
    3. Review Query Fingerprints sorted by impact — inspect bubble chart spikes.
    4. Optimize All Queries (or top N via settings) to populate index recommendations.
    5. Export Index DDL for change review, or Create Indexes + Validate to measure EXPLAIN improvement on the server.
    6. For hard cases, use row ⚡ Optimize to open the full Query Optimizer (rewrites, visual explain, trace).
    7. Truncate or rotate logs after a tuning pass so the next analysis is not skewed by fixed queries.

    Privileges & troubleshooting

    • Integrated load needs SHOW GLOBAL VARIABLES, digest-table SELECT, and schema privileges for EXPLAIN on your queries.
    • Upload path works offline — only file read access on your machine.
    • If mysql.slow_log or digest buttons stay disabled, check the tooltip on the button or the home error banner for the server reason.
    • PostgreSQL Not installed badge → run CREATE EXTENSION pg_stat_statements in the connect-through database and ensure the library is preloaded.
    • Empty Recommended Indexes after Optimize All → statement may not be optimizable, or no index would help (check row tooltip).

    Tips

    • Prefer Query Digest / pg_stat_statements for ongoing triage — faster than parsing multi-gigabyte log files.
    • Use Top 5 or Top 10 Optimize All scope first on large workloads; widen after reviewing results.
    • Group by fingerprint surfaces ORM/query-builder patterns that raw log lines hide.
    • Pair batch index creation with the Query Optimizer Create Index flow when you need single-query rewrite guidance alongside DDL.
    • Related: Performance Monitor for live server metrics; Query Profiler for session-level timing.
