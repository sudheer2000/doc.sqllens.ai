Query Optimizer

The Query Optimizer Workbench is a VS Code webview for MySQL: live EXPLAIN in several formats, structured index recommendations (with optional CREATE INDEX / ALTER TABLE … ADD INDEX), algorithm trace for debugging TT and index decisions, and optional before/after validation after you apply an index. This page is the product-facing feature map; the unified guide also links here from skyline-product-guide.html#qo-overview.

Premium. Opening the optimizer workbench is gated behind the Skyline premium feature code qo (see assertPremiumFeatureAllowed in the extension). Exact entitlements depend on your org and product flags.

What it does

For a SQL statement against your connected MySQL schema, the workbench runs optimizer analysis: normalized query text (from the server when JSON EXPLAIN is available), traditional and extended EXPLAIN output, heuristic rewrite hints, and an index recommender that considers join graph, WHERE shape (including OR policy), GROUP BY / ORDER BY, and live information_schema where needed.

  • Non-destructive by default — analysis and EXPLAIN do not change data; index creation is explicit.
  • Schema-coupled — recommendations are tied to the active connection and database context (the workbench resolves schema nodes when opened from a connection without a selected database).
  • Operational guardrails — suggested ALTER TABLE statements are executed in isolation and normalized to reduce syntax issues; the editor path can strip optimizer comment artifacts before running SQL elsewhere in the product.

How to open

Entry pointWhat happens
Command Palette → Optimize Query (Visual Explain) Opens the workbench for SQL from the active SQL editor selection or document.
Command Palette → Open Query Optimizer (from live EXPLAIN hint) Opens from inline diagnostics / hint flow when available.
Result / query panel → open optimizer Passes the current SQL into the workbench (MySQL connections).
Optimize All Queries with Index Recommendations (+ optional Debug variant) Batch optimization over multiple statements in scope; debug variant increases index pipeline logging.
Slow query log / performance tools Some flows open the workbench with SQL (and sometimes target database context) from a template or log entry.
Performance monitor / template “Explain” actions Can launch the workbench with a stored sample query for that template.

Exact command titles may include a sqllens.ai: prefix depending on build; search the palette for “Optimize” or “Query Optimizer”.

Workbench layout

SQL panes

  • Your query — editable SQL (Monaco).
  • Optimizer query — optional read-only pane showing the statement MySQL exposes for analysis when EXPLAIN FORMAT=JSON (or related) supplies a rewritten/normalized form. Use Refresh Optimizer Query when it is empty but JSON succeeded.

Primary toolbar (overview)

  • Analyze — recommendations & inline index/rewrite summary (default detail view).
  • Explain — tabular EXPLAIN.
  • Visual explain — graphical plan (can be disabled globally; see Settings).
  • Rewrites / Tips — dedicated tab for rewriter output.
  • Format / Clear — formatting and reset of the SQL panes.
  • Trace — human-readable algorithm trace (see below).
  • Copy Index DDL — copies actionable ALTER TABLE … ADD INDEX (or related) statements.
  • Create Index — guided create with preflight impact where applicable; supports single and multi-index flows.

Analyze, recommendations & transaction table (TT)

The index recommender classifies tables using join roles, EXPLAIN access types, and local filters. It chooses a transaction table (TT) per plan block for multi-table queries and scores candidates. You will see both primary suggestions and optional / alternative indexes (for example when two trailing strategies compete, or when a refinement is secondary).

  • Primary recommendations — shown first; included by default in bulk “Create indexes” checks.
  • Optional alternatives — same panel, clearly labeled; bulk UI leaves them unchecked by default so you opt in deliberately.
  • Existing index labels — recommendations may reference whether an identical or prefix/subset index already exists (exact / prefix / set), with adjusted messaging.
  • Impact & confidence — heuristic labels driven by estimated rows and rule outcomes (not a guarantee of production speedup).
Join vs filter. The optimizer often shows join predicates inside WHERE in the rewritten SQL — the trace explains which equalities were interpreted as join edges vs local filters when debugging TT and index eligibility.

EXPLAIN views

  • Traditional table — classic EXPLAIN columns.
  • Visual explain — node graph for quick intuition.
  • TREE — hierarchical text plan (EXPLAIN FORMAT=TREE) when supported.
  • JSON — raw JSON for tooling or deep inspection.

Setting skyline-mysql.queryOptimizer.disableVisualExplain hides visual explain rendering if your environment hits webview rendering limits.

Algorithm trace

The Trace button switches the overview detail panel to a structured, human-readable log: clause split, join graph, TT selection rationale, eligible columns, EXPLAIN rows used for scoring, and final index decisions. Use Refresh Trace after changing SQL or rerunning analysis.

Implementation lives in the workbench trace panel and index debug pipeline; verbose JSON dumps are optional via settings (below).

Rewrites / tips

The Query rewriter suggests structural or stylistic improvements (non-DDL). Review each suggestion against your semantics and compatibility requirements before adopting.

Index suggestions & AI recommendations

Inside the richer index UX, you can switch between internal (rules + EXPLAIN + catalog) suggestions and optional AI recommendations when your org enables LLM-backed flows. AI output is advisory; validate with EXPLAIN and your workload.

Create index, bulk create & validation

Single index

  • Preflight can summarize table size/engine and qualitative risk before ALTER.
  • DDL executes as an isolated statement to avoid batching mistakes.
  • After success, the workbench collects EXPLAIN before/after and presents a comparison view; optional profiler-based validation is available where supported when you explicitly choose validation.

Bulk create

  • Select multiple DDL rows; optional indexes start unchecked.
  • Progress and per-index outcomes are summarized after the run.

Closing the result pop-up triggers a refreshed full analysis so the plan and recommendations reflect the new indexes.

Optimize all queries

The Optimize All Queries with Index Recommendations command analyzes many statements from the current editor context and surfaces index opportunities in aggregate. Use the Debug variant when you need extended recommender traces in logs for support or regression work.
